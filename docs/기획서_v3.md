## 3. 핵심 컨셉

| 가져올 요소 (피크민 블룸) | 걸음이 곧 성장 · 함께 걷기 · 장소마다 다른 만남 |
| 캠퍼스에 맞춘 변형 | 지금 시간 · 계절 · 날씨에 맞춰 경희스팟 25곳에서 코스를 고름 · 만남 스팟 10곳 지붕 위에 그 자리의 경희몬이 서 있어 약속 장소가 됨 · 지도와 버튼 색이 계절에 따라 바뀜 |

| 차별점 | ① AI 가 오늘의 맥락과 장소 소개글만 근거로 코스 이유를 씀 ② **지금 근처에서 같은 시간 걷고 싶은 학생**과 공개된 만남 스팟에서 만남 (AI 대화 주제 3개) ③ 걷기 보상이 파트너 성장으로 이어져 혼자서도 다시 걷게 함 |
| 캐릭터 | 랜드마크 동물 24종 경희몬 (C 4 · B 4 · A 8 · S 8), 진화 3단계 (예: 아기 올빼미 → 중앙도서관 올빼미 → 빛나는 중앙도서관 올빼미) |

## 5. AI 활용 계획
| 항목 | 작성 |
| --- | --- |
| AI 가 맡는 일 | ① 추천: 서버가 점수로 고른 후보 10곳 + 지금 맥락(시간 · 계절 · 날씨 · 식후) + 장소 소개글 → 코스 순서와 장소별 이유 ② 매칭: 두 사람의 취향 · 시간대 · 만남 스팟으로 대화 주제 3개 ③ 검사 · 연결: 글 · 사진 · 인상착의 통과/보류/거절, 공지 → 장소 · 요약 |
| 사용 모델 · 도구 | 학교 챗쿠(FactChat) AI 게이트웨이의 경량 모델 (Azure 에서 막혀 AWS Lambda 중계로 호출) · 기상청 단기예보 API |
| AI 가 필요한 이유 | 같은 장소라도 "가을 저녁 · 비 · 식후 15분" 같은 조합마다 다른 이유를 자연스러운 문장으로 써야 하고, 처음 만난 두 사람의 공통점에서 대화를 여는 일은 규칙으로 하기 어렵다 |
| 품질 관리 | 후보 밖 장소는 서버가 버림 · 거리 · 시간은 서버가 계산 · 이유는 소개글에 없는 사실이면 규칙 이유로 바꿈 · 주의 문장(출입 제한 등)은 이유로 쓰지 않음 · **출입 제한 스팟(기숙사 등 5곳)은 후보에서 뺌** · AI 실패 시 규칙 · 예시 20개로 대체 |
| 이점 측정 | 서버가 AI 추천과 규칙 추천을 나눠 **수락률 · 완주율 · 코스 별점**을 집계 (`/api/admin/stats`), AI 대신 규칙으로 처리한 비율도 집계 |
| 비용 | 추천 1회 수백 토큰 · 경량 모델 · 중계는 Lambda 무료 범위 (실측 `[시범]`) |
