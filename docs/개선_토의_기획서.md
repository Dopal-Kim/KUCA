## 2. AI 산책 추천 고도화 🔴

| 현재 | 개선안 |
| --- | --- |
| 입력은 걸을 시간과 취향 칩뿐. AI 는 건물 이름만 보고 고름. 규칙 추천과 차이를 보여 줄 근거 없음 | 입력에 **날씨·시간대·계절·남은 공강·장소별 최근 쪽지 요약·스팟 소개글** 추가 → "지금 가야 하는 이유"를 근거와 함께 출력. AI/규칙 결과를 나눠 기록해 비교 |

**토의할 것**
- 장소 소개글(숨은 명소 설명)을 누가 몇 곳 쓸지 (제안: 경희스팟 전체, 장소당 2~3줄)
- 쪽지 내용을 추천에 쓸 때의 개인정보 범위 (닉네임 빼고 내용만?)
- 비교 실험 방식: 사용자 반은 AI, 반은 규칙? 아니면 두 코스를 같이 보여 주고 고르게?
- 모델: 지금 `gpt-5.4-mini`(구형으로 분류됨) → 후속 경량 모델로 바꿀지

## 3. AI 쪽지·댓글 검사 (안전한 공유 공간) 🔴

| --- | --- |

## 4. AI 공지 → 장소 연결 🟠

| 현재 | 개선안 |
| --- | --- |
| 서버에 공지 API 없음. 앱은 항상 `[예시]` 공지 | 학교 공지 원문 → AI 가 관련 장소·요약 판별 → 장소 화면에 원문 링크와 함께 표시 |

## 5. 사람을 잇는 기능 (매칭·함께 걷기) 🔴

| 현재 | 개선안 |
| --- | --- |
| 친구·매칭·협동 모두 없음. 사람 사이 기능은 쪽지 좋아요뿐 → "혼자 하는 수집 게임"으로 보임 | **최소 버전**: 같은 주에 같은 코스·장소를 좋아한 3~4명을 AI 가 묶어 "함께 걷기 퀘스트" 제안 → 닉네임으로 참여, 동의 후 인원 공개 |

**토의할 것**
- 매칭 방식: 실시간(지금 근처) vs 주간 그룹 (제안: 주간 그룹이 구현·안전 모두 쉬움)
- 만남 방식: 같은 시간에 같이 걷기 vs 각자 걷고 결과 공유 (안전·부담)
- 최소 버전만 할지, 협동 포획까지 갈지
- 신고·차단을 어디까지 만들지
