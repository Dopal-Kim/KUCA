# v2 서버 연동: 정해야 할 것 · 팀에 알릴 것 (10/23, B)

C 의 서버(#44 추천 v2 · #45 매칭 · #46 산책 완료 · #47 · #48)를 Azure `kuca-memo` 에 배포하고, 앱을 C 명세(`docs/api.md` v2)에 맞췄다 (PR #49).
실제 Azure 서버로 혼자 산책(시작 → 완료 → 리뷰)과 함께 산책(매칭 → 수락 → 도착 → 함께 걷기 → 완료 → 리뷰)을 끝까지 확인했다.
그 과정에서 나온 것들을 급한 순서로 정리한다.

## ✅ 1. AI(챗쿠 · BAZE 게이트웨이)가 Azure 에서 막히던 문제 — 중계로 해결 (10/23)

**원인**
- Azure(일본 동부) 서버에서 게이트웨이를 부르면 게이트웨이 앞단이 **`403 Forbidden`** 으로 막았다. 같은 키로 맥(한국)에서 부르면 정상.
- Azure for Students 는 리전 정책상 **한국 리전을 쓸 수 없다** (허용: centralindia · indonesiacentral · uaenorth · japaneast · malaysiawest).
- AWS Lambda(시드니)를 거치면 게이트웨이가 정상으로 받는다 → 국가 차단이 아니라 **Azure 서버 쪽만 막는 것**.

**해결: AWS Lambda 중계 (B 의 AWS 계정, 무료 플랜 · 시드니 ap-southeast-2)**
- 함수 `kuca-ai-relay` (코드 `tools/relay/lambda_function.py`): 비밀 경로로 온 POST 만 게이트웨이에 그대로 넘긴다. 키는 Lambda 에 저장하지 않는다 (Azure 가 보낸 Authorization 을 그대로 전달).
- Azure 앱 설정 `Recommend__Endpoint` = 중계 주소 (비밀 경로 포함, 저장소에 넣지 않음). 추천 · 스몰토크 · 내용 검사 · 공지 분류가 모두 이 설정을 같이 읽는다.
- 확인: 추천 `source: ai` (2.7~3.8초), 리뷰 글 내용 검사 AI 1회 성공 (`/api/admin/health`).
- 되돌리기: `Recommend__Endpoint` 를 지우면 바로 예전(직접 호출)으로 돌아간다.

**남은 것**
- [ ] AWS 무료 플랜은 **183일(약 2027-04) 또는 크레딧 $100 를 다 쓰면 계정이 닫힌다.** 그 전에 플랜 업그레이드(요금은 Lambda 무료 범위라 거의 0원)나 다른 방법으로 옮기기
- [ ] 중계 계정 주인(B) 외에 접근할 사람 정하기 (B 가 없을 때 장애 대응)
- [ ] C: `server/README.md` 에 중계 설정 한 줄 추가

## 🔴 2. 시연용 가상 상대가 꺼져 있음

- 지금은 **실제 상대가 있어야만** 매칭된다. 심사위원 혼자서는 매칭 → 함께 걷기를 체험할 수 없다.

## 🟠 3. 날씨 키가 Azure 에 없음

- 앱 설정에 `Kma__ServiceKey` 가 없다 (`/api/admin/health` 의 `weatherKey: false`).
- 그래서 추천 응답의 `context.weather` 가 늘 `null`: 비 · 눈 오는 날 실내 스팟 가산점, 날씨 맞춤 스몰토크가 동작하지 않는다.

**정할 것 (C)**
- [ ] 공공데이터포털 기상청 키를 Azure 에 넣기: `KMA_KEY="..." ./deploy-azure.sh` (`server/README.md` "날씨")

## 🟠 4. 레벨을 어디서 셀지 (앱 vs 서버)

- **앱 HUD 레벨**: 기기 안 경험치 (걷기 1km 10, 경희몬, 퀘스트, 완료 보상 …) 로 센다.
- **서버 레벨** (`GET /api/me/progress`): **서버를 거친 산책**의 경험치만 센다 (걷기 · 완료 · 함께 · 리뷰).
- 둘이 다른 숫자가 된다. 지금 앱은 HUD 와 맞추려고 **완료 화면도 기기 레벨**을 보여 주고, 서버 보상(완료 · 함께 경험치, 완료 티켓)만 기기 저장에 더한다 (걸은 거리 경험치는 걸을 때 이미 더했으므로 뺀다).

**정할 것 (B · C)**
- [ ] A안 (지금): 레벨은 앱, 서버는 산책 기록 · 지표용
- [ ] B안: 레벨은 서버 값만 (D9 "앱은 받은 값만 표시"). 대신 경희몬 · 퀘스트 경험치도 서버로 보내는 API 가 필요
- [ ] 체험 계정은 7일 뒤 지워지므로, 서버 레벨이면 시연 계정 레벨도 7일마다 초기화됨

## 🟠 5. 추천에 "출입 제한" 장소가 나옴

- 기본 추천 예시 (식후 30분): `제2기숙사 남자동` · `제2기숙사(여자동)` · `우정원`, 이유가 **"거주자 외 출입 제한"**.
- 규칙 문구가 소개글의 마지막 문장을 쓰기 때문에, 기숙사 소개글의 주의 문구가 그대로 추천 이유가 됐다.

**정할 것 (A · C)**
- [ ] A: `spots.json` 에 출입 제한 표시 (예: `"restricted": true`) 를 넣거나, 기숙사를 추천 후보에서 빼기
- [ ] C: 출입 제한 스팟은 후보에서 빼고, 규칙 문구에 주의 문장이 오지 않게
