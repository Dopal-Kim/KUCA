# 안드로이드 배포 — Unity 에서 빌드 → Firebase App Distribution

새 기능을 팀원·테스터 폰에 보내는 방법입니다. **빌드 담당 1명**이 Unity 에서 APK 를 만들어 Firebase 에 올리면, `kuca-team` 그룹 폰에 "새 버전" 알림이 가고 App Tester 앱에서 업데이트됩니다.

```
빌드 담당 PC: Unity 메뉴 KUCA › 안드로이드 APK 빌드  (10~20분)
   → Builds/Android/KUCA-0.1.<번호>.apk
   → Firebase 콘솔 › App Distribution 에 끌어다 놓기 → kuca-team 선택 → 배포
   → 테스터 폰: 알림 → App Tester 에서 업데이트
```

- **서버 쪽 변경(쪽지·AI 추천·날씨)은 이것과 상관없이 바로 반영됩니다.** 이 배포는 앱 쪽(화면·게임 규칙·3D 모델) 변경용입니다.
- GitHub 자동 빌드는 보류했습니다 (7장). Unity Personal 라이선스는 GitHub 서버에서 활성화할 수 없기 때문입니다.

## 1. 이미 끝난 준비 ✅
| 항목 | 상태 |
| --- | --- |
| Firebase 프로젝트 `kuca-f7095` · 안드로이드 앱 `com.mungim.kuca` | ✅ |
| 서명 키 `kuca.keystore` (alias `kuca`) | ✅ — 원본과 비밀번호는 빌드 담당이 보관, **저장소에 올리지 않음** |
| `google-services.json` | 받아 두기만 함. 지금은 쓰지 않음 (저장소에 올리지 않음) |

## 2. 남은 준비 (한 번만)
1. **테스터 그룹**: Firebase 콘솔 → App Distribution → **테스터 및 그룹** → 그룹 추가 → 별칭 `kuca-team` → 팀원 3명 메일 추가
    - 실사용 테스터(10~20명)는 나중에 별도 그룹(예: `kuca-pilot`)으로
2. **빌드 담당 PC**: Unity Hub 에서 Unity 6 에 **Android Build Support**(OpenJDK, Android SDK & NDK 포함) 모듈 설치
3. **서명 키 파일**을 빌드 담당 PC 의 프로젝트 폴더 **밖**에 둠 (예: `문서/KUCA-keys/kuca.keystore`)

---

## 3. 배포할 때마다 (빌드 담당)

### ① 최신 코드 받기
- GitHub Desktop 등으로 배포할 브랜치(`main` 또는 `feature/android-support`)를 최신으로 받고 Unity 로 엽니다.

### ② APK 빌드
1. Unity 위쪽 메뉴 **KUCA › 안드로이드 APK 빌드 (Firebase 배포용)**
2. 창에서
    - **서명 키 파일**: "찾기"로 `kuca.keystore` 선택 (한 번 고르면 이 PC 에 기억됨)
    - **Alias**: `kuca`
    - **키스토어 비밀번호 · Alias 비밀번호**: 입력 (저장되지 않음 — Unity 를 다시 켜면 다시 입력)
3. **빌드 → KUCA-0.1.N.apk** 버튼
    - 빌드 대상이 안드로이드가 아니면 먼저 전환합니다 (처음엔 오래 걸림). 전환이 끝나면 버튼을 다시 누릅니다
    - 버전 코드가 자동으로 1 올라갑니다. 빌드가 실패하면 원래 번호로 돌아갑니다
4. 끝나면 APK 가 있는 폴더가 열리고 "Firebase 열기" 를 물어봅니다

### ③ Firebase 에 올리기
1. [Firebase 콘솔 → App Distribution](https://console.firebase.google.com/project/kuca-f7095/appdistribution) (위 창의 "Firebase 열기")
2. 앱이 **KUCA (Android, com.mungim.kuca)** 인지 확인
3. **APK 파일을 화면에 끌어다 놓기** → 업로드가 끝날 때까지 대기
4. **테스터 및 그룹**에 `kuca-team` 추가
5. **출시 노트**: 바뀐 점 한두 줄 (예: "꾸미기 추가, 쪽지 사진 업로드 고침")
6. **배포** 클릭 → 그룹 폰에 알림

### ④ 버전 기록 남기기
- 빌드로 `My project/ProjectSettings/ProjectSettings.asset` 의 버전 두 줄(`bundleVersion`, `AndroidBundleVersionCode`)이 바뀝니다. 이 변경을 커밋해서 다음 빌드 번호가 겹치지 않게 합니다 (커밋 메시지 예: `Android 0.1.3 배포`)
- 서명 키 경로는 빌드가 끝나면 원래대로 돌려 두므로 ProjectSettings 에 남지 않습니다

---

## 4. 테스터(팀원 포함)가 할 일 — 처음 한 번
1. 안드로이드 폰에서 Firebase 초대 메일 열기 → **시작하기** → 구글 계정으로 수락
2. 안내에 따라 **Firebase App Tester** 설치
3. App Tester 에서 KUCA → **다운로드** → "출처를 알 수 없는 앱 설치" 허용 → 설치
4. 이후 새 버전이 올라오면 알림 → App Tester 에서 **업데이트**

---

## 5. 자주 나는 문제
| 증상 | 원인 · 해결 |
| --- | --- |
| 메뉴에 KUCA › 안드로이드 APK 빌드가 없음 | 최신 코드를 받았는지, Console 에 빨간 컴파일 오류가 없는지 |
| 빌드 버튼이 회색 | 서명 키 파일·비밀번호 두 개를 다 넣었는지 |
| "Keystore was tampered with" / 비밀번호 오류 | 키스토어 비밀번호 또는 Alias 비밀번호가 틀림 |
| 빌드 실패 (Android SDK/NDK 관련) | Unity Hub 에서 Android Build Support 모듈과 그 안의 OpenJDK·SDK·NDK 를 설치했는지 |
| 폰에서 "앱이 설치되지 않음" | 예전 APK 가 다른 키로 서명됨 → 한 번 지우고 다시 설치. 이후로는 같은 키라 업데이트됨 |
| 테스터에게 알림이 안 감 | 배포할 때 `kuca-team` 그룹을 넣었는지, 테스터가 초대를 수락했는지 |

## 6. 보안 정리
- `kuca.keystore` 와 비밀번호: 빌드 담당 + 백업 1곳(개인 드라이브 비공개 폴더 + 비밀번호 관리자). 잃어버리면 모든 테스터가 앱을 지우고 다시 깔아야 하고, 나중에 Google Play 에 올릴 때도 필요합니다
- 지금 방식에서는 GitHub Secrets 가 필요 없습니다. 이미 등록한 Secrets 는 7장을 다시 쓸 때를 위해 두어도 되고, 지워도 됩니다
- Firebase 서비스 계정 JSON 키도 지금은 쓰지 않습니다. 다운로드 폴더의 파일은 지우고, 필요하면 Google Cloud 콘솔에서 키를 삭제해도 됩니다

## 7. GitHub 자동 빌드 (보류)
`.github/workflows/android-firebase.yml` 은 남겨 두었지만 자동으로 돌지 않습니다 (Actions 탭 수동 실행만).

- **멈춘 이유**: Unity Personal(무료) 라이선스는 다른 컴퓨터(GitHub 서버)에서 활성화할 수 없습니다. 수동 활성화 웹페이지도 Enterprise·Industry 좌석만 지원합니다
- **다시 켜는 방법** (필요해지면)
  - 팀원 PC 를 GitHub 빌드 머신(self-hosted runner)으로 등록 → 그 PC 의 Unity 로 빌드
  - 또는 Unity Pro 시리얼이 생기면 `UNITY_SERIAL` Secret 추가
  - 그다음 워크플로의 `on:` 에 `push` 를 되살림
