## 2. 설문 결과 → 문제 정의 확정 🔴
A 가 설문 결과를 5분 공유한 뒤 정합니다.

## 3. 함께 걷기 설계 🔴 (B 화면 · C 서버 · A 근거)
기획서의 핵심("사람을 잇는 AI")인데 아직 없는 기능입니다. 범위를 여기서 정해야 B·C 가 동시에 시작할 수 있습니다.

| 질문 | 선택지 | 제안 |
| --- | --- | --- |
| 만남 방식 | ① 같은 시간에 같이 걷기 ② 각자 걷고 결과 공유 ③ 둘 다 | ② 로 시작 (안전·부담 적음), 원하면 ① |
| 그룹 크기 | 2명 / 3~4명 / 제한 없음 | 3~4명 (설문 "몇 명이 좋은지" 반영) |
| 묶는 주기 | 실시간(지금 근처) / 주 1회 | 주 1회 |
| 묶는 방법 | AI 가 묶음 / 규칙 점수 + AI 는 이유만 / 규칙만 | 규칙 점수 + AI 가 이유·코스 (AI 실패해도 동작) |
| 연락 수단 | 앱 안 그룹 쪽지 / 오픈채팅 링크 / 없음 | 앱 안 그룹 쪽지 (기존 쪽지 검사 재사용) |
| 공개 범위 | 닉네임만 / 학과·학년까지 | 닉네임 + 공통 취향만 |
| 안전 | 신고·차단 / 나가기 / 관리자 검토 | 셋 다, 신고 1건이면 그룹에서 숨김 |

## 4. AI 추천 비교와 데이터 🔴 (C 서버 · B 앱)
심사 질문 "AI 를 쓴 효과가 있나?"에 R8 수치로 답하려면 지금 방식을 정해야 합니다.

**정할 것**
- 비교 방식: ① 사용자 절반은 규칙 추천만 ② 두 코스를 같이 보여 주고 고르게 ③ 날짜별로 번갈아
  (제안: ① — 수락률·완주율 비교가 깔끔함)
- 무엇을 기록할지: 추천 표시 · 코스 시작 · 완주 · 쪽지 작성 · 그룹 참여 (기기 ID·시간·추천 방식)
- 쪽지 내용을 추천에 쓸 때 범위: 검사 통과한 쪽지만 · 닉네임 제외 · 최근 며칠
- 테스터에게 기록 수집을 어떻게 알릴지 (개인정보 안내 화면 문구)
