## 2. 루트 추천

### 확인된 문제

| # | 등급 | 문제 | 근거 (재현) | 고칠 방향 |
| --- | --- | --- | --- | --- |
| R1 | **P0** | **지어낸 사실이 사용자에게 나감** | 가짜 AI 가 "루프탑 카페에서 아메리카노가 2000원이에요" → 국제대학 이유로 그대로 노출. 근거 검사(`IsGrounded`)는 이유의 **한글 두 글자 조각 하나**만 소개글과 겹쳐도 통과 | 근거 검사를 "소개글 문장과 겹치는 비율 ≥ 50%" 로 올리거나, 이유를 **소개글 문장 중 고르기**(AI 는 문장 번호만 답)로 바꾸기. 숫자 · 가격 · 시간이 소개에 없으면 버리기 |
| R2 | **P0** | **위험한 행동 권유가 나감** | "국제학관 옥상 난간에 올라가면 야경이 좋아요" 가 3곳 모두 통과 (건물 이름 조각이 겹쳐서) | 금지어(옥상 · 난간 · 담 · 출입금지 · 밤늦게 혼자 …) 검사 + 위 R1 |
| R3 | **P0** | **AI 답 형식 하나로 서버 500** | 답의 `content` 가 배열(`[{type:"text",text:…}]`, 최신 채팅 API 형식)이면 `ReadAnswer` 의 `GetValue<string>()` 가 `InvalidOperationException` → `ChatKuClient` catch 에 없음 → 500. 앱은 기기 추천으로 넘어가 화면은 버티지만 서버 추천 · 지표 · 기록은 날아감 | catch 에 `InvalidOperationException` 추가 + 배열이면 text 를 이어 붙이기 (두 줄) |
| R4 | P1 | **운영에서 AI 가 조용히 꺼져 있을 수 있음** | 요청에 `temperature: 0.7` 을 넣는데 운영 모델은 `gpt-5.4-mini`. GPT-5 계열은 temperature 를 거부(400)하는 경우가 있고, 그러면 **항상 "기본 추천"** 으로 나가도 아무 경고가 없음 (장애 주입에서 400 → fallback 확인) | 운영 `/api/admin/stats` 의 AI 호출 성공률 확인 (5장). 400 이면 temperature 를 빼기. AI 성공률이 50% 미만이면 관리자 health 에 경고 |
| R5 | P1 | **30분을 골랐는데 10분 코스** | 정상 AI 답: 3곳 604 m · 걷기 10분 (예산 24분). 들를 곳 최대 3곳 + 가까운 순이라 짧게 끝남. 화면에 "30분" 을 고르고 "10분" 코스가 나옴 | 예산의 60% 미만이면 한 곳 더 · 돌아오는 길 포함 · 또는 "약 10분 + 둘러보기 20분" 으로 문구 |
| R6 | P1 | **AI 가 고른 곳이 걸러지면 코스가 1곳만** | 없는 ID · 중복이 섞인 답 → 남은 1곳(2분)만 나감 | 남은 수가 MaxStops 보다 적으면 규칙 추천으로 채우기 |
| R7 | P2 | AI 제목을 검사하지 않음 | 낮인데 "밤 산책" 제목이 그대로 | 제목도 R2 금지어 · 시간대 단어 검사, 아니면 규칙 제목 |

### 잘 된 것 (유지)
- AI 실패 · 시간 초과(20초) · 400 → 규칙 추천으로 넘어감, 앱은 30초까지 기다림 ✅
- 후보 밖 ID · 중복은 버림 ✅, 출입 제한 스팟은 후보에서 뺌 ✅
- 화면에 "AI 추천 / 기본 추천" 표시 ✅, 식후 걷기 건강 문구 + "의료 조언 아님" ✅
- 코드 블록에 감싼 JSON · 앞뒤 잡담도 읽음 ✅

## 3. 산책 메이트 매칭 + 첫 대화 주제

> 매칭 자체는 **AI 가 아니라 규칙**(건물 거리 − 공통 취향 × 100 m). 공모전 설명에서 "AI 매칭" 이라고 하면 안 됨 — "규칙 매칭 + AI 대화 주제" 가 정확.

| # | 등급 | 문제 | 근거 (재현) | 고칠 방향 |
| --- | --- | --- | --- | --- |
| M1 | **P0** | **AI 대화 주제를 검사 없이 처음 만난 두 사람에게 보냄** | 가짜 AI 가 "혹시 연락처 교환하실래요?" · "애인 있으세요?" · "어느 동네 사세요?" → 그대로 전달 (프롬프트에 "사적인 질문 금지" 만 있고 출력 검사 없음) | 주제마다 이미 있는 내용 검사(`IContentModerator`) + 금지 주제어(연락처 · 번호 · 카톡 · 애인 · 연애 · 사는 곳 · 집 · 나이 · 외모 · 정치 · 종교) → 하나라도 걸리면 예시 주제로 |
| M2 | P2 | "다음 주제" 가 같은 주제를 다시 줌 | 다음 주제 요청 → 앞과 같은 3개 (AI 가 같은 답을 하면 그대로) | `Already` 와 겹치면 버리고 예시로 채우기 |
| M3 | P2 | 거리 상한 없음 | 정문 ↔ 천문대도 매칭 (대기자가 둘뿐이면 거리 무관) | "인근" 이라고 설명하려면 1 km 상한 또는 화면에 "만남 장소까지 n분" 표시 |

### 잘 된 것 (유지)
- 성별을 안 정하면 대기열에 못 들어감(403) ✅, "동성만" 은 다른 성별과 절대 안 묶임 ✅ (실행 확인)
- 차단 · 신고 3회 제외 · 거절 1시간 · 응답 60초 · 노쇼 10분 ✅, 위치 · 인상착의는 메모리에만 ✅
- 인상착의는 내용 검사를 거침 ✅, 가상 상대는 체험 계정에만 · 지표에서 제외 ✅

| N4 | P1 | **운영 AI 요약이 들쭉날쭉** | 요약이 있는 4개 중 1개(10/22)만 AI 가 다시 쓴 문장, 3개(10/20)는 본문 앞부분 그대로 = AI 실패 시 대체 방식 | 5장의 지표로 AI 성공률 확인 |

## 5. 검증 못 한 것 · 팀이 확인할 것

1. **운영에서 AI 가 실제로 쓰이는 비율** — `curl -H "X-Admin-Key: …" https://kuca-memo.azurewebsites.net/api/admin/stats` 의 AI 호출(recommend · smalltalk) 성공 비율. 0% 에 가까우면 R4(temperature) 가 원인일 가능성이 큼. (관리자 키는 C)
2. 운영 모델(gpt-5.4-mini · claude-haiku-5-5)로 실제 답 품질 — 지어내기 · 사적인 질문이 실제로 얼마나 나오는지는 키로 20~30번 돌려 봐야 앎. 이번 검토는 "**나왔을 때 막는가**" 만 봤고 답: 막지 못함.
3. 날씨(기상청 키)는 로컬에 없어 "날씨 모름" 으로만 돌려 봄.
